# WaveWordBridge formal verification (SymbiYosys)

Timing, integrity and translation checks for the RISC-Q → QICK adapter `WaveWordBridge`
(`risc-q/src/riscq/soc/rf/WaveWordBridge.scala`, identical on branch `waveword-bridge` `6839f648` and on the
integration branch `claude-newdesign` `708f2da5`), with the parameters that integration uses
(`QickGenParams`: `leadTime = 32`, queue depth 8).

The bridge turns RISC-V register writes (`RfCmd`) into QICK's 168-bit signal-generator word and
releases it at a scheduled time through a `TimedQueue`. QICK's `sg_translator` then converts the
word into the 160-bit command `axis_signal_gen_v6` (SGv6) consumes. SGv6 itself is the kept QICK
hardware, verified separately (`main:firmware/formal/`).

Scope: the bridge, plus the bridge → `sg_translator` path up to SGv6's command input. Julia's
SpinalSim tests (`WaveWordBridgeSim`, `WaveWordBridgeGenSim`) cover one pulse each; this suite covers
every command sequence the solver can find within the task depth: **when** words come out, in what
order, whether any are lost or changed, what SGv6 decodes, and what happens under pressure.

## How to run

```
source ~/tools/oss-cad-suite/environment
./run_all.sh                     # all tasks, ~5 min on 8 cores
./run_all.sh p1 cov tr_func      # selected tasks
./run_all.sh --summary           # sby's summary of the last runs
gtkwave bridge_p7/engine_0/trace.vcd &
```

If the bridge changes, regenerate the Verilog (`mill runMain riscq.soc.rf.WaveWordBridgeGen 32`
in `risc-q/`, from a terminal **without** OSS CAD Suite sourced), copy `risc-q/gen/wwb_lead32/WaveWordBridge.v`
over `WaveWordBridge.v` and rerun. For another lead, also set `LEAD` in `bridge_formal.sv` and `wave_png.py`.

## Evidence (all written by sby, not by our scripts)

- **Overall summary:** `sby bridge.sby --taskstatus` reads sby's status database (`bridge/`) and
  prints one line per task, `PASS` or `FAIL`. At the end of a run, sby also prints
  `The following tasks failed: [...]` (last line of `run_all.log`).
- **Per task**, in `bridge_<task>/`:
  - `PASS` / `FAIL` (empty file, the name is the verdict)
  - `logfile.txt` (ends with `DONE (PASS, rc=0)` or `DONE (FAIL, rc=2)`)
  - `bridge_<task>.xml` (JUnit report)
  - `config.sby` (exact configuration of the task)
  - `src/` (exact copies of the sources that were checked)
  - `model/design.log` (Yosys build log)
  - `engine_0/`: for a FAIL, the counterexample as `trace.vcd` (GTKWave) and `trace_tb.v`
    (replays the exact inputs in a Verilog simulator such as Vivado xsim); for a cover, one
    `trace<N>.vcd` per reached cover
- **Per property:** `sby bridge.sby --status` (or `--statusfmt csv`) lists each assert/cover.

## Model

- One clock. At Julia's 500 MHz, 1 cycle = 2 ns. This matches `claude-newdesign`, where SGv6 runs
  on the RISC-Q DSP clock.
- `io_time` is a counter that advances by 1 every cycle (the SoC batch-time counter).
- The CPU is replaced by **free inputs**: on every cycle the solver may write any value to any
  register address, or nothing.
- The harness keeps a copy of the bridge's registers. On each fire it records the expected
  168-bit word, the full 32-bit values the CPU wrote, and the `startTime`, then checks every
  `io_wave` handshake (and, with `TRANSLATOR`, SGv6's 160-bit command) against that record.
- The reference for the translator check is **SGv6's own field decoding**
  (`firmware/ip/axis_signal_gen_v6/src/ctrl_sg_v6.sv:427-435`), not the translator's code.
- Rules of use (assumptions), so the guarantees are about legal use:
  - fire at least `32 + MARGIN` cycles before `startTime` (default `MARGIN = 3`)
  - startTimes fired in increasing order, at least `TGAP` cycles apart (default 3)
  - at most `K` fires tracked (default 3), `startTime ≤ TMAX`
  - SGv6 always ready (except in the P7 tasks)
  - for `tr_func`: CPU values fit SGv6's fields (nsamp and env < 2^16, gain a signed 16-bit value,
    conf bits above 4 zero)
- Bounded: every PASS holds for all input sequences up to the task depth (25 cycles; 30 for P6).
  Every guarantee has a cover task showing the checked situation actually occurs.
- Engine: `smtbmc boolector` (4 s for the 168-bit data task; yices took more than 10 minutes).

## Results

Three kinds of task:

- **Guarantee**: all rules of use kept. A FAIL would be a bridge bug.
- **Limit**: one user rule loosened on purpose, to measure what happens when software breaks it.
  The strict version is expected to FAIL; the tolerance versions measure by how much.
- **Robustness**: a situation the user cannot rule out (SGv6 busy, many pending pulses,
  out-of-range values). A FAIL is a real issue.

"Late" is measured against `startTime − 32`, the release time the bridge is designed for.
The "never early" check never failed in any task.

### Guarantees: all PASS

| ID | Check | Task(s) | Result |
|---|---|---|---|
| **P1** | each word released exactly at `startTime − 32`, never early or late | `p1` | **PASS** |
| covers | 1 word out; 2 words; back to back (2 cycles apart); 3 pending at once | `cov` | **all reached** |
| **P5** | every word out exactly once, in fire order, all 168 bits equal to what was written | `p5_data`, `p5_order` | **PASS** |
| **P8** | reset with words pending: nothing stale afterwards, new words work | `p8`, `cov_p8` | **PASS** (covers reached) |
| **TR** | bridge → `sg_translator`: SGv6's decoded freq, phase, envelope address, gain, nsamp, outsel/mode/stdysel/phrst equal the CPU's values; reserved bits zero; valid/ready pass through | `tr_func`, `cov_tr` | **PASS** (covers reached) |

### Limits of the rules of use: measured, well behaved

| ID | Rule loosened | Task(s) | Result |
|---|---|---|---|
| **P2** | fire margin | `p2_m*` | margin 3 exact; margin 2/1/0 → **1/2/3 cycles late**. Fire ≥ **35 cycles (70 ns)** ahead for exact timing |
| **P3** | time order (later-fired word due earlier) | `p3` | late: head-of-line blocking (same as tProc's head-only FIFO) |
| **P4** | spacing between startTimes | `p4_g*` | gap ≥ 2 exact; gap 1 → 2 late (3rd word); gap 0 → 3–4 late (3rd word; ≤ 4 proven). At most **one word every 2 cycles (4 ns)** |

### Robustness: real issues

| ID | Situation | Task(s) | Result |
|---|---|---|---|
| **P7** (A) | SGv6 not ready on the release cycle | `p7`, `cov_p7` | **FAIL**: `io_wave.valid` is a 1-cycle pulse that ignores `ready`; the word is **lost** |
| **P6** (B) | more than 9 pulses pending | `p6_k9`, `p6_k10` | 9 **PASS**; 10th **FAIL**: capacity 9 (8 FIFO + 1 head stage); the 10th fire is **silently dropped** |
| **B4** | `nsamp` 0 or 1 | `b4` | **FAIL**: passed through; SGv6 then plays about 65536 cycles (finding F9) |
| **TR-trunc** | CPU writes a value wider than SGv6's field | `tr_trunc_nsamp`, `tr_trunc_env`, `tr_trunc_gain`, `tr_trunc_conf` | **FAIL** (each on its own field): nsamp, envelope address and gain are cut to 16 bits, conf bits above 4 are dropped. No error is raised; e.g. nsamp 65536 becomes 0, which SGv6 plays as ~65536 cycles |

## The bridge's contract, as verified

| Guaranteed by the bridge (+ translator) | Must be guaranteed by the user of the bridge |
|---|---|
| release exactly at `startTime − 32` (64 ns), so SGv6 starts the pulse at `startTime` | fire **≥ 35 cycles (70 ns)** before `startTime` |
| never early | startTimes in **increasing order**, **≥ 2 cycles** apart |
| exactly once, in order, word unchanged | at most **9 words** pending |
| SGv6 decodes exactly the CPU's values (when they fit its fields) | SGv6 **always ready** on the release cycle (or the bridge needs a fix) |
| reset clears pending words | `3 ≤ nsamp < 2^16`, env address `< 2^16`, gain a signed 16-bit value |

## Items for the controller team

1. **P7: the word is lost under backpressure.** SGv6's command FIFO deasserts `tready` when full
   (19 commands, see `main:firmware/formal/README.md`). On `claude-newdesign` (`QickGen.scala`) that
   `tready` is wired back to `io.wave.ready`, but the bridge never reads it, and the tests there play
   one pulse per channel, so `ready` never drops. It drops when commands pile up in SGv6, i.e. when
   pulses are scheduled closer together than their lengths. Options: hold the word in a small output
   register until `ready` (adds about 1 cycle: lead 33), or document "pulses never overlap" as a
   software rule and add a drop/overflow flag.
2. **P6: silent drop at 10 pending fires.** RISC-Q's register writes are posted, so the CPU cannot be
   stalled the way tProc pauses its core. Options: software credit counting (≤ 9 in flight), a
   readable occupancy/overflow status register.
3. **B4 / TR-trunc: no range checks.** The bridge forwards any `nsamp`, envelope address and gain;
   the translator silently keeps 16 bits. Clamp, reject or flag out-of-range values in the bridge or
   in software (QICK does this in its compiler).
4. **P2/P4: scheduling rules** for the compiler or runtime: fire ≥ 35 cycles ahead, startTimes
   ≥ 2 cycles apart and in order. Violations make words late, never early.
5. **P8 depends on wiring.** The bridge clears on *its* reset. In the native RISC-Q SoC, `riscqReset`
   does not reach the DSP clock domain (earlier finding), so check that the reset the controller uses
   for abort actually reaches the bridge.

## Comparison with the tProc path

tProc numbers: teammates' formal proofs (`main:firmware/formal/README.md`, one-clock model) and
our QICKEmu characterization (`verification/timing/`, branch `verification/timing-characterization`).

| Item | tProc v2 → SGv6 | WaveWordBridge |
|---|---|---|
| release relative to schedule | due + 4 t_clk (≈ 9.3 ns at 430.08 MHz) | `startTime − 32` (64 ns early): SGv6's 32-cycle accept → output latency, so the pulse starts at `startTime` |
| minimum lead | ≥ 9 cycles (`tp_lead8` PASS) | ≥ 35 cycles = lead 32 + 3 (P2) |
| exactly once, in order | yes (`tp_order`) | yes (P5) |
| output under backpressure | holds `tvalid`, but `tdata` can change (`tp_disp` FAIL, our F1) | drops the word (P7) |
| capacity | 512 per port on hardware (16 in the formal model); **stalls the core** when full | 9; **drops** the 10th |
| out-of-range length | nsamp wraps (`tp_len` FAIL) | nsamp, env, gain truncated (TR-trunc) |
| `nsamp` < 3 | passes through (F9) | passes through (B4) |

## Limits

- **Bounded depth** (25–30 cycles, up to 9 words). Long sustained traffic (e.g. more than 16 pushes,
  where the FIFO pointers wrap) is not covered.
- **One clock**, as in `claude-newdesign`. A design that puts SGv6 on its own clock (599.04 MHz in
  QICK's r23 build) would add a clock crossing, which is not modelled.
- **Small time values**, near 0. TimedQueue compares times as a signed difference, valid only within
  ±2^31 cycles of `io_time`; the `startTime = 0` wrap trap documented in `TimedQueue.scala` is not
  exercised.
- **One stressor per task.** Combined pressure (SGv6 busy while the queue is nearly full) is not run
  as a single task.
- Not covered: the readout trigger path (`io_trig`), and what SGv6 plays (verified separately).
- One parameter set (lead 32, depth 8, as integrated). The suite (without the translator tasks) was
  also run once with the default lead 8: every verdict and failure step was identical, so the
  behaviour scales with the lead (minimum fire lead = lead + 3). Those results are not committed.
