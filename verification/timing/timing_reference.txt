1. HOW A COMMAND FLOWS
----------------------

        c_clk (200 MHz, core)              t_clk (430 MHz, timeline)                  sg_clk (599.04 MHz, generator)
 +------------------------------+   +----------------------------------+   +---------------------------------------+
 | E0i  core issues port write  |   | E1  cmd visible on timeline side |   | E3  SGv6 accepts cmd (s1_axis)        |
 |  |                           |   |  |                               |   |  |                                    |
 |  v                           |   |  v                               |   |  v                                    |
 | E0   pushed into wave FIFO   |-->| compare time_abs > due --> pop   |-->| E4  SGv6 loads it and starts playing  |
 |      (due time fixed here)   |CDC|  |                               |CDC|  |                                    |
 +------------------------------+   |  v                               |   |  v                                    |
                                    | E2  tProc releases (m0_axis)     |   | E5  output enable on/off (en_o)       |
                                    +----------------------------------+   |  v                                    |
                                                                           | E6  first non-zero DAC sample (opt.)  |
                                                                           +---------------------------------------+

Four timing layers:
 1) Absolute time   : time_abs[47:0], +1 per t_clk (qproc_time_ctrl.sv)
 2) Reference time  : c_time_ref[47:0] on c_clk, set/incremented by core time instructions (qproc_ctrl.sv)
 3) Dispatch        : due = sext(p_time) + c_time_ref, stored in wave FIFO {cmd[167:0], due[47:0]};
                      released when time_abs_r > due (strict), head only, >= 3 t_clk between pops
 4) Transport + SG  : shared CDC FIFO (SG0-2) -> combinational translator -> SGv6 FIFO -> READ_ST/CNT_ST FSM;
                      SGv6 plays when idle, nsamp (sg_clk cycles) sets length.
                      Start = max(arrival + L, end of previous pulse)

4. CRITICAL TIMING CHARACTERISTICS (hypotheses from RTL, to confirm or refute)
------------------------------------------------------------------------------
 C1  Release is strictly after due: time_abs > due (strict), release offset ~4 t_clk, constant.
 C2  One release per >= 3 t_clk per port (2-cycle blank after each pop).
 C3  Per-port FIFO is in issue order; only the head is compared (head-of-line blocking; no reordering by time).
 C4  Late command (due already passed) releases immediately; no error flag.
 C5  Core stalls when any dispatcher FIFO is full (unless TPROC_CFG[11]); commands are never dropped.
 C6  SGv6 start = max(arrival + L, previous end); back-to-back pulses are gapless (period = nsamp).
 C7  Due time is on the t_clk grid, duration on the sg_clk grid (different clocks).
 C8  SG CDC FIFO is shared by SG0-2: one stalled SG stalls all three.
 C9  SGv6 writes its FIFO on tvalid alone: an adapter must never assert tvalid while tready is low.
 C10 Emulator-model latencies (E0->E1, E2->E3, E3->E4) are not hardware numbers:
       time adder ignores carry-in (+dt vs +dt+1 on update); dispatcher FIFO = Verilator variant;
       CDC fifo_dc_sv uses 16-stage wptr sync; SGv6 FIFO = fifo_behav; DDS = model.
